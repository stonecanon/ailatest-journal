Root cause (three stacked code defects)
  • ① Over-frequent scheduled job: cron set to */15 * * * * (every 15 minutes).
  • ② Over-wide backfill window: each run re-scanned the last 90 days of event data for traffic classification.
  • ③ UPDATE with no dedup filter: the UPDATE only filtered by time range, not by "already classified", so already-classified rows were rewritten every run. D1 bills UPDATEs per row even when the value is unchanged.
Fixes deployed (2026-08-20, same day)
  • ✓ Disabled the high-frequency cron, keeping only a once-daily 12 16 * * *
  • ✓ Narrowed the backfill window from 90 days to 1 day
  • ✓ Added AND (traffic_type='' OR visitor_hash='') so the UPDATE only touches unclassified rows
